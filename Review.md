# AI Code Review, Troubleshooting, and Iterative Refinement

## 1. Initial AI Generation & Approach
To accelerate the development of SIS 2, an AI model was used to outline a basic test suite structure using Python, `pytest`, and `playwright`. The initial code covered the 5 mandatory test cases for `https://practicesoftwaretesting.com/`:
1. Home page title validation.
2. Product keyword search.
3. Product details navigation.
4. Add-to-cart workflow.
5. Contact form page navigation.

## 2. Iterative Troubleshooting and Code Modifications
During the initial local test runs (`pytest -v --headed`), the AI-generated code required several critical manual fixes and refinements:

- **API Method Mismatch (`get_by_id`):** 
  - *Issue:* The initial code generated by the AI attempted to use `page.get_by_id()`, which resulted in an `AttributeError` because Python's Playwright API does not implement this method (resembling JS/TS syntax conventions).
  - *Resolution:* Manually refactored all ID-based lookups to use standard CSS locator syntax: `page.locator("#element-id")`.

- **Asynchronous UI Timing & Cart Counter Failure:** 
  - *Issue:* In Test Case 4 (Add to Cart), asserting the exact text `'1'` on the cart badge counter immediately after clicking caused a test failure (`AssertionError: Locator expected to have text '1'`). The shopping cart badge update relies on an asynchronous JavaScript response from the backend, creating a race condition.
  - *Resolution:* Replaced the counter assertion with a more reliable check for the application's green toast notification (`page.get_by_text("Product added to shopping cart.")`), which ensures the action is properly acknowledged by the UI before verification.

- **Snake_case Convention Alignment:** 
  - *Issue:* Ensured all assertion matchers strictly complied with Python's naming conventions (e.g., verifying `to_be_visible()` and `to_have_text()` instead of camelCase alternatives).

## 3. Justification
These adjustments were necessary to transform a generic AI-generated prototype into a robust, deterministic test suite. Handling API limitations and asynchronous UI states eliminated test flakiness, ensuring reliable execution across all 5 test suites with a 100% pass rate.
